# AI 助手边界

## 适合首期验证

| 能力 | 输入 | 输出 | 上线控制 |
|---|---|---|---|
| 商品资料草稿 | 供应商表格、发票/装箱单图片、商品标签 | SKU、名称、规格、单位、条码字段及不确定项 | 字段来源可查看；员工确认后保存 |
| 自然语言库存查询 | 用户问题 | 基于库存 API 的数量、位置和更新时间 | 缺数据时说明缺失，不编造库存 |
| 上架建议 | 商品类别、货位容量、固定货位规则 | 候选货位及理由 | 扫描实际货位并确认 |
| 操作指导 | 角色、当前流程和错误提示 | 下一步指引、错误解释 | 不绕过权限和流程校验 |
| 数据质量提示 | 商品/货位/动作记录 | 重复 SKU、缺字段、异常差异提示 | 只提示，不自动合并或删除 |

## 不允许模型直接决定

- 不允许仅凭图片推断商品身份后自动增加库存。
- 不允许自然语言对话直接扣减、转移或调整正式库存。
- 不允许模型绕过登录、审批、库存不足或批次规则。
- 不允许将客户原始数据默认用于微调 MiniMind 或训练其他模型。
- 不允许将“模型说成功”作为业务成功；以库存 API 返回和审计记录为准。

## 建议的操作模式

1. AI 解析请求并生成结构化草稿。
2. 业务 API 校验 SKU、单位、数量、权限、货位和可用库存。
3. 界面清楚展示将发生的变化。
4. 员工扫码复核并确认；高风险调整由负责人二次审批。
5. 成功后显示交易编号并写入审计流水。

## 数据保护

- 尽量只向模型发送完成任务所需字段，避免整库或整批采购文件外传。
- 为云模型配置供应商、用途、保留策略和用户授权说明。
- 允许仓库关闭 AI 功能后继续完成核心扫码流程。
- 模型失败或超时必须回退到人工表单，不能阻塞入库、出库和盘点。
- 先用规则和评测集验证效果，再讨论训练；初期通常无需训练自己的基础模型。
