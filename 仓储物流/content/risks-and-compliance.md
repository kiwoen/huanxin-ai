# 风险与合规

| 风险 | 影响 | 预防与应对 | 状态 |
|---|---|---|---|
| 商品/货位数据不干净 | 扫码无法匹配、库存错位 | 先清洗脱敏样本；设置唯一编码；期初盘点双人核对 | 待调研 |
| 员工漏扫或错扫 | 系统账与实物分离 | 商品与货位双扫描、回显确认、异常拦截和抽盘 | 高优先级 |
| 网络不稳定 | 操作延迟或重复提交 | 先测试覆盖；请求防重；离线能力单独评估 | 待确认 |
| 多人并发改同一库存 | 负库存或重复出库 | 数据库事务、锁定/预留和防重标识 | 设计要求 |
| AI 识别错误 | 错建商品或误导查询 | 草稿与来源提示；人工确认；库存变化只走业务 API | 设计要求 |
| 账号权限过宽 | 未授权调账或数据泄露 | 最小权限、负责人审批、定期审查、审计日志 | 设计要求 |
| 数据丢失 | 无法恢复真实库存和操作历史 | 自动备份、异地副本和定期恢复演练 | 设计要求 |
| 开源许可/插件边界不清 | 不能按预期分发或商用 | 选型前核对仓库、依赖和插件许可，必要时请专业人士审阅 | 待选型 |
| 需求不断扩张 | 工期、成本和质量失控 | MVP 范围冻结；新需求进入下一阶段评估 | 项目控制 |

## 运营与数据保护

- 仓储记录可能包含供应商、客户、员工账号、订单和商业敏感信息；只采集必要信息并设定访问权限。
- 先明确部署位置、日志保留、备份责任、账号注销和数据导出/删除流程。
- 如调用第三方模型或识别服务，应告知客户数据可能发送至何处、用途为何，并提供不用 AI 的核心操作路径。
- 不把客户库存数据或真实操作日志默认写入公开训练集或模型微调集。
- 使用开源软件时应核对当前版本、依赖与商用分发条件；本项目书不替代法律审查。

## 条码与可追溯

优先识别商品现有条码并建立映射，内部货位可使用企业自定义标签。若业务涉及多组织供应链、批次/效期或托盘级追溯，再评估 GS1 标识规则和行业要求，避免随意把自定义码当成全球标准码。
