# 需求清单

## 使用角色

| 角色 | 主要操作 | 权限建议 |
|---|---|---|
| 管理员 | 建用户、商品、货位、单位和基础设置 | 配置权限；不得无痕删改历史动作 |
| 仓库负责人 | 审核盘点差异、调整、库存报表 | 可审批高风险库存调整 |
| 仓库操作员 | 扫码收货、上架、拣货、移库和盘点 | 只能执行被授权的业务动作 |
| 只读查询者 | 查询库存和货位 | 不得写入库存 |

## 功能需求优先级

| ID | 优先级 | 需求 | 验收说明 |
|---|---|---|---|
| FR-01 | P0 | 商品和货位建档/导入 | 必填字段校验；重复编码能提示 |
| FR-02 | P0 | 记录库存收货、出库、移库 | 每次变更形成带操作者、时间和数量的记录 |
| FR-03 | P0 | 条码/二维码扫码识别商品和位置 | 扫错、未登记或无权限时明确拦截 |
| FR-04 | P0 | 查询商品总量和分货位数量 | 页面显示统计时间和库存状态 |
| FR-05 | P0 | 盘点与差异审批 | 盘点值不直接覆盖历史；差异形成调整单 |
| FR-06 | P0 | 用户角色、审计记录和数据备份 | 能查谁在何时提交了什么操作 |
| FR-07 | P0 | 商品单位与包装换算 | 箱、包、件等换算明确且经负责人确认 |
| FR-08 | P1 | 批次、效期、序列号和待检状态 | 由商品类型和行业规则决定是否启用 |
| FR-09 | P1 | 导出和低库存提醒 | 提醒可配置，不自动下采购单 |
| FR-10 | P1 | AI 从表格/单据提取商品草稿 | 导入前展示字段、来源和不确定项供人确认 |
| FR-11 | P2 | 多仓、订单和第三方系统集成 | 仅在单仓试点证实需求后规划 |
| FR-12 | P1 | 退货/返库与库存预留 | 先确认来源单据、质检状态和可用库存规则 |

## 核心数据对象

- **商品：** 内部 SKU、名称、规格、基本单位、包装单位及换算、分类、供应商编码、条码别名、是否按批次/序列号追踪、是否需效期管理、启用状态。
- **货位：** 仓库/区域/货架/层/格的父子层级、货位码、货位类型、容量和状态。
- **库存维度：** 至少区分商品、货位和库存状态；适用时还要区分批次、序列号、容器。
- **库存余额：** 可用、已预留、待检/隔离、损坏等适用状态，不把“仓库里有”简单等同于“可以出库”。
- **库存动作：** 单据号、类型、商品、数量和单位、来源/目标货位、批次/序列号、操作人、时间、关联单号、状态、调整原因和防重标识。
- **用户与角色：** 账号、权限范围、所属仓库和操作状态。

## 非功能要求

| 类别 | 初始要求 |
|---|---|
| 一致性 | 同一业务操作不得重复扣减；并发更新需事务保护 |
| 可追溯 | 库存动作有审计记录；更正用反向/调整记录，不静默覆盖 |
| 易用性 | 手持设备可用，大按钮、少打字、扫码后明确显示结果 |
| 安全 | 最小权限、账号保护、传输加密、定期备份和恢复演练 |
| 可用性 | 现场网络条件待测；是否支持离线是立项决策项 |
| 可维护性 | 商品、位置和单位规则可配置；关键动作有测试 |

## 数据迁移原则

先复制一份现有 Excel/ERP 数据做测试导入，生成异常清单：重复 SKU、空条码、单位不一致、无效货位和负库存。只有仓库负责人核对确认的数据才进入正式试点库；原始数据保留只读副本。

## 需要业务方拍板的规则

- 商品按件、箱、包等多单位收发时，换算关系由谁维护，能否出现小数数量。
- 退货是直接回到可用库存，还是先进入待检/隔离区。
- 已分配给订单但尚未出库的库存是否应标为预留，谁可以解除预留。
- 是否允许负库存；若不允许，系统必须在过账前阻止。
- 盘点期间若同时发生出入库，如何冻结、标记或复核盘点结果。
