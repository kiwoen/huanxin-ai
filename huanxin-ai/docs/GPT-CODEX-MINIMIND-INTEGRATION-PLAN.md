# GPT + Codex + MiniMind 集成任务板

## 目标

在不破坏现有幻炘 AI 功能的前提下，建立可回滚的多模型与 Harness 扩展路线：

- GPT：复杂推理、教师数据、评测与方案设计；
- Codex：代码实现、测试、重构与文档维护；
- MiniMind：本地轻量模型、路由、分类与结构化决策；
- 幻炘 AI：统一任务循环、工具、记忆、审批、审计和知识库。

## 任务项目表

| 编号 | 任务 | 状态 | 验收标准 |
|---|---|---|---|
| 1 | 记录当前仓库基线和未提交改动 | 已完成 | 不覆盖用户已有改动 |
| 2 | 建立目标架构与集成边界 | 已完成 | 文档明确模型、Harness、工具和治理职责 |
| 3 | 盘点现有 LLM Provider 接口 | 进行中 | 明确最小适配面 |
| 4 | 增加 MiniMind Provider/配置 | 待开始 | 可通过统一接口调用本地 OpenAI 兼容服务 |
| 5 | 增加结构化 Decision 接口 | 待开始 | 输出受 schema 校验的动作和置信度 |
| 6 | 建立工具选择与风险判断评测集 | 待开始 | 至少 100 条 JSONL 样本 |
| 7 | 接入 GitHub/文件/RAG 工具 | 待开始 | 只读任务可完成并写入审计 |
| 8 | 建立 Harness 任务循环适配层 | 待开始 | 最大步数、失败重试、停止和审批可控 |
| 9 | 本地 Windows/WSL2 部署验证 | 待开始 | MiniMind + 幻炘 AI 可启动 |
| 10 | 回归测试、模型评测和文档同步 | 待开始 | 测试通过且有评测报告 |

## 修改边界

1. 不删除或覆盖工作区已有用户改动。
2. 不自动推送 GitHub，不直接修改远程仓库。
3. 不让模型绕过现有审批、沙箱和审计机制。
4. 先增加适配层，再决定是否移植外部 Harness 源码。
5. 每一阶段都保留测试和回滚路径。

## 第一阶段完成定义

- 现有测试基线已知；
- MiniMind 作为 OpenAI 兼容本地服务可配置；
- 不配置 MiniMind 时现有行为不变；
- 能够识别并拒绝不完整的结构化决策输出；
- 文档和配置示例已同步。
